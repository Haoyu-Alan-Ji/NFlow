## Locked simulation design

All multilayer simulations use:

- `n = 5000`
- `p = 200`
- `s = 10` active predictors (5% of predictors)
- Gaussian noise variance `sigma2 = 1`
- noise-free signal SD `1.5`
- fitted ReLU MLP `200 -> 20 -> 20 -> 1`
- DSS-LVR mode `feature_unit_induced_edge`
- role-aware affine IAF, `K = 6`, `cyclic3`
- normalized-ReQU structural training map
- 2000 epochs, 300 all-on warmup epochs
- posterior draws `32 / 128 / 500`
- ten paired data seeds `400,...,409`

The active labels are fixed at predictors 1--10 across replicates so selected sets are directly comparable for Kuncheva stability. X, teacher supports, teacher weights, interactions, and noise are regenerated by seed.

The teacher has six nonlinear components and exactly two active predictors per component. Twelve predictor-component memberships cover ten active predictors, so a small amount of repeated use occurs naturally.

## Main Table 1: predictor selection across nonlinear conditions

Five conditions are generated from the same `n/p/s` backbone:

1. ReLU
2. ReLU + 2 raw pairwise interactions
3. ReLU + 2 quadratic terms
4. Trigonometric ridge teacher
5. Trigonometric ridge teacher + 2 raw pairwise interactions

There is **no ReLU interaction + quadratic condition**.

The explicit interaction is a standardized raw product `x_j * x_k`, **not** `sin(x_j) * cos(x_k)` or another product of transformed trigonometric terms. In the trigonometric-interaction setting, interaction pairs are preferentially taken from predictor pairs that already occur together in a two-predictor teacher unit.

Main Table 1 contains only selection metrics:

- TPR
- FPR
- selection Accuracy
- AUROC
- AUPRC
- selected support `|S_hat|`
- Kuncheva

MSE and R2 are saved in the raw CSV for diagnostics but are deliberately omitted from the main Table 1.

Kuncheva uses the top-10 predictor score/PIP set from each replicate and averages all pairwise indices. This is replicate-level reproducibility (sampling + optimization), not an initialization-only measure.

## Main Table 2: function recovery and structural sparsity

The fixed DGP is **trigonometric + 2 raw interactions**, with six teacher units and two predictors per unit.

Rows:

1. DSS-LVR
2. LBBNN-LRT
3. LBBNN-FLOW
4. ISLaB-FLOW
5. SS-GL
6. SS-GHS
7. IS-ANN-L1

Main columns:

- signal MSE
- signal R2
- Kuncheva when a predictor score/ranking exists
- `D_param`
- `network_density` (`D_E` in the paper)
- `path_density` (`D_pi` in the paper)
- runtime

Definitions:

- `D_param`: retained connection weights in the final hard/native sparse network divided by candidate connection weights in the corresponding dense architecture; biases excluded.
- `network_density`: method-native active-edge/network density. For DSS-LVR this is posterior expected induced-edge density.
- `path_density`: fraction of complete active input-output paths. For DSS-LVR this is posterior expected active-path density evaluated draw-by-draw.

All three are intentionally retained. `D_param`, posterior expected/native edge density, and complete-path density summarize different structural objects and are not duplicate versions of one sparsity number.

Kuncheva is computed for DSS-LVR, the LBBNN/ISLaB rows, and IS-ANN-L1 using their predictor scores. SS-GL and SS-GHS select hidden nodes rather than predictors, so predictor Kuncheva is reported as `--`.

## Output policy

The main scripts save only compact CSV summaries, generated LaTeX tables, and one main figure per experiment. They do not save epoch histories or model checkpoints by default. Summary CSVs retain mean estimates and 95% confidence intervals; the generated LaTeX tables use the compact mean-only layout and can be changed later if the manuscript needs CI display.

## Important interpretation notes

- Table 1 answers predictor-selection robustness across nonlinear conditions; its main table has no MSE/R2.
- Table 2 answers function-recovery versus structural-sparsity behavior on one fixed DGP.
- `D_param`, network density, and path density must all be retained in Table 2.
- Lower density alone is not a better result; it must be interpreted together with MSE/R2.
- SS-GL/SS-GHS have no predictor-level Kuncheva because they are hidden-node methods.
- wsBNN is discussed in the Introduction and noted below the comparison table but is not rerun in the common structural benchmark because the released regression workflow is not a clean non-oracle common-benchmark implementation without substantial adaptation.
